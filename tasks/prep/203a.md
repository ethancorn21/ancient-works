# Prep notes for task 203a: The batch, US — the 90 US built sites

One paragraph: `fit/batch_us.py` runs, per US site, candidates (plans.json rows whose `sites`
contains the site) → 202's proposed pairs → `plan_fit.similarity` → 001's gate. Accepted
placements become automatic platefit documents (existing format + `"auto": true` + gate `score`)
in `data/db/platefits/`; everything else becomes a review item in 201's format in
`data/review/`; a site left with nothing gets a "no picture found" item. The 20 human hand-fit
docs and the 19 hand-fit `site.json` files are pinned by `tests/golden/hand_fit_docs.sha256`
(committed BEFORE the first batch write) and must be byte-identical after the run. 203b imports
the same loop (`fit/batch_us.py`) pointed at the other 294 sites (all `region != "US"` plus the 6
region-less sites — confirmed in 203b's file); parent 203 later checks union coverage.

## 1. Assumptions — what the dependencies provide

**001 (gate) — seen on its branch** (hand-over on agent/c; NO code on the branch yet):
- Will provide: `pipeline/fit_gate.py` (predicted name), `docs/gate.md` (pre-registered rule +
  thresholds + results table), `tests/test_gate.py`, committed per-fit input caches
  `data/gate/*.npz` (`.npz` is NOT gitignored; only `data/autofit/*.npz` is).
- Gate = conjunction of numeric checks: (1) pair-consistency residuals of the solved transform;
  (2) old-map correlation (plate ink vs the site's old-map ink) vs a search-matched null — the
  main discriminator for 60 m / 10° / 15% / cross-site wrong fits; (3) DEM ridge score vs
  searched null as a bonus where relief is strong. A strict gate is fine (GOAL); everything
  refused goes to review.
- Fit representation (its words): a placement = (site, plate crop, transform), transform =
  `plan_fit.similarity`'s `a, b` with `merc = a*(u-1j*v)+b` (pairs page px → lon/lat). Gate input
  = that triple; it fetches DEMs at runtime when a cache is absent (US = 3DEP).
- **Contract the batch assumes (INFERRED — R1):** a callable judging a placement, returning
  accept/reject + a numeric score, e.g. `fit_gate.check(site, plan, a, b, crop, pairs, ink=…)
  -> (bool, float, detail)`. The batch calls it through ONE adapter fn (`gate_placement`) so the
  real signature slots in at start without touching the loop.

**200 (evidence) — inferred** (its task file; same wave 1):
- Adds an `evidence` field to `data/commons/files.jsonl` and `data/books/index.jsonl` rows (kind:
  P373 category / P180 depicts / caption+coords / hand-tied QID + specifics + checked date). NO
  plans.json row carries it today (0/1166; `cols` have no evidence column) → **the batch never
  requires `evidence`**; passes it through "when present".
- Lookup (verified): book row → `data/books/index.jsonl` row with the same `id`

### 2.1 `fit/batch_us.py` (box 2) — CLI: `python3 fit/batch_us.py [--root DIR] [--sites id …]
[--working] [--golden]`
- `us_sites(root)` — the 90 ids (`region=="US"`).
- `candidates(site_id, rows)` — plans.json row dicts whose `sites` contains the site id.
- `row_evidence(row)` — 200's field via the §1 lookup, or None.
- `plate_image(root, site_id, row, working)` — path or None. Order: (1) built
  `web/data/sites/<sid>/plan_<plan>.webp` (in-repo on this VM for the 4 US hand fits); (2)
  `data/raw/books/<ia>/full/<file>` (present in the architect's checkout, absent on this VM);
  (3) `data/raw/commons/<site>/<h>.jpg`; (4) only with `--working`: fetch — commons via
  `plan_fit.load_picture`'s code path (reuse, don't reimplement), book via `pipeline/books.py`'s
  `full` command. Tests never reach (4).
- `gate_placement(root, site_id, row, a, b, resid, working)` — `(accepted, score, why)`, THE
  single adapter to 001 (R1). Missing inputs (no old-map ink, no DEM, no plate image) →
  **fail closed**: reject, `why` names the missing conjunct (GOAL: a strict gate is fine).
- `write_doc(root, site_id, row, proposal, score)` — `data/db/platefits/<site>.<plan>.json` via
  `aw.save_json` (atomic), **skipped when the file already exists** (never-touch invariant).
  Shape = the existing format + `"auto": true` + `"score": <float>` (book vs commons keys as
  §1; `crop` = row `map_box` scaled to the `size` frame, int px, or the full frame; `pairs` =
  202's output verbatim, 1 dp px / 7 dp lon-lat; `at` = run timestamp).
- `write_item(root, site_id, entries, no_picture=False)` — upserts `data/review/<site>.<lead>.
  json` in 201's format (one per site; entries = `{plan, title, evidence?, url, pairs, coarse?,
  gate_score?, why?}`; the `no_picture` variant has empty `candidates` + `no_picture_found:
  {"searched": "web/data/plans.json (N rows, matched by the sites field)", "at": …}` — PLAN
  assumption 3). Never clears `resolved`.
- `run_sites(root, site_ids, working=False, gate=None)` — the importable loop 203b points at its
  own list (`gate=None` → 001 adapter; a stub callable in tests):
  1. remember whether the site is already hand-fitted (a platefits doc for it; for 203b also
     `site.json["plate"]["fit"]`);
  2. candidates whose doc already exists → skip (never touch);
  3. each other candidate: `propose_for` → `similarity(pairs)` → gate → accept: `write_doc` +
     record; reject: item entry + record;
  4. if the site ends with no doc, no rejected candidate, and was NOT hand-fitted →
     `no_picture` item (covers "no candidates at all" and "only candidate was a skipped
     hand-fit doc"); if it WAS hand-fitted → nothing (box 3's "or an existing hand fit");
  5. returns per-site records `{site, auto: [plan…], rejected: [plan…], hand_fit, no_picture,
     gate_inputs: "ok"|"missing:<what>"}`.
- `write_report(root, records, sample_n=20)` — `docs/batch_us.md` (box 5): counts (automatic
  fits / review items / already hand-fitted / no picture found), the **recorded seed** (module
  constant, e.g. `SEED = 20261010`; `random.Random(SEED).sample` over the auto list; 20 where
  ≥20, else all), a per-candidate table (site, plan, doc id or item, score, why), a gate-inputs
  availability breakdown (R7), and the seeded 20-sample table with a page URL each
  (`<page>#<site-id>`, hash route — R8).
- `--golden` — regenerates `tests/golden/hand_fit_docs.sha256` (box 1).

**Full working-phase run (box 3):** `python3 fit/batch_us.py --working` on the real checkout,
all 90: plate images fetched as needed (IA / Wikimedia), 001's gate fetches its own DEMs (3DEP)
