# Prep notes for task 202: Proposed point pairs — a placement a person finishes in a minute

One paragraph: `fit/propose.py` (stdlib-only, importable, + a small CLI) computes, per (site, picture row), a STARTING
POINT: an anchor (recorded scale + rotation where trustworthy, else a coarse one) mapping the row's map-panel centre to
the site centre, plus 3–5 proposed pairs (`[[u, v, lon, lat]]`, page px of the row's `size` frame → lon/lat) on the drawn
panel's corners + centre. It is never a fit: no snapping, no texture search (that bet failed, docs/autofit.md 0/5), no
gate call, no writes. Consumers: 201 stores the dict verbatim in review items; 203a/b feed `pairs` to
`plan_fit.similarity` as the model's starting point.

## 2. Verified code/data facts (this checkout, 2026-10-11)

### plan_fit (read-only, `pipeline/plan_fit.py`)
- `similarity(pairs) -> (a, b, resid_m, k)`: complex least squares, `merc = a*(u - i*v) + b`, `a = s·e^{iθ}`;
  `resid_m` in **ground metres** (`= |a·w+b−z| · k`), `k = aw.ground_scale(mean lat) = cos(lat)`. The 4-tuple (not the
  2-tuple the old notes said — old R note, corrected).
- `build(doc)`: doc pairs are in the **doc `size` frame**; `fs = im.width/size[0]` scales them to the full scan;
  **book docs without `size` fall back to the raw file's size** (serpent-mound doc has `size: null` → raw
  [2884,4064] = the row's `full_size`, verified). Depictions entry: `fit.m_per_px = |a|·k / f` and
  `fit.rot_deg = degrees(angle(a))` where **`f` is the 2400-px crop resize factor** → **the stored `m_per_px` is in
  crop-image px, NOT the doc frame**. For any comparison use `similarity(doc["pairs"])` recomputed, never the stored
  depfit numbers. Pairs are never moved or snapped (invariant).
- `pipeline/aw.py`: `to_merc(lon,lat) -> (x, y)` Mercator metres tuple, `to_lonlat(x,y)`, `ground_scale(lat)=cos(lat)`.
  All 202 needs; no network.
- **Rotation convention (measured, verified):** with `a = s·e^{iθ}` and image-v-down, θ=0 is north-up; positive θ
  rotates the plate counter-clockwise as drawn. The old-style affine below uses the same convention
  (`atan2(m10, m00)` of M equals `fit.rot_deg`; newark −95.39 ✓).
- `tools/fitkit.py ground(sid)`: `web/data/sites/<sid>/relief.jpg` if present, else Esri aerial at 1 m/px (the site
  box). 202 records which ground the pairs refer to as `"relief"`/`"aerial"` — rule: site has `lidar: false` →
  `"aerial"`, else `"relief"` (verified: exactly 17 sites have `lidar: false`, and they are exactly the ones whose
  `web/data/sites/<id>/` dir lacks `relief.jpg`; **none of the 17 has a plans.json candidate** — the aerial branch is
  exercised in 202's test via a synthetic/asserted case, not a real row). 202 never reads or fetches the image.
