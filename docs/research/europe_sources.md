# Europe: open LiDAR, historical maps and historic aerials - source catalogue (Phase 3 research)

Compiled 2026-10-10 from inside a sandbox whose network blocks almost every website. (Its JSON twin `europe_sources.json` stayed on the cloud branch `claude/amazing-carson-c779pq`. Rows marked memory are unverified.)

**210 records**: 64 LiDAR/DTM, 81 historic aerial/orthophoto, 48 historical map, 17 book. Evidence: 14 fetched here (bytes), 171 from third-party files fetched from GitHub raw, 2 from official files, 3 from web-search results, 20 from memory. Reachable from this container: 14; blocked: 172; no endpoint: 24.

Already covered by the owner and therefore NOT re-documented: S3 `mapseries-tilesets` (NLS tiles), `srsp-open-data` (Scotland LiDAR), `open-lidar-data` (data/BE CH DE DK EE ES FI FR IE LT LU LV NL PL SE SI UK US). Entries for them are cross-references only.

## 1. Read this first

- **status / evidence** - `BYTES FETCHED`: I fetched bytes from that endpoint here (only AWS S3 hosts and GitHub raw are reachable). `3rd-party file`: the URL / layer id was read from a file fetched from GitHub raw (ELI, lidar2map, Mapterhorn, terrain-viewer, Freemap, osmbe, heritage-aerial survey, ...) - its `[src]` link is the pinned file. `official file`: read from an official project file or document. `web search`: seen in a search result. `memory`: recalled, unverified (endpoint left empty or flagged).
- **tags in notes** - `[tv]` = jo-chemla/terrain-viewer registry (author probed each service for an image with CORS on 2026-10-05); `[tv-custom]` / `[tv-unusable]` = its elevation library and its rejected-services survey; `[fm]` = FreemapSlovakia/freemap-v3-react `scripts/national-sources.json`; `[ha]` = fabio-rovai/open-ontologies heritage-aerial scouting survey (live probes 2026-09-02). I could not re-test any of those hosts.
- **reachable** - whether the host answered from this container (it is blocked for everything except AWS S3, GCS, GitHub, package registries). **CORS yes (fetched)** = header observed here; **yes/no (reported)** = stated by the registry author; `?` = unknown.
- **access** - open / free-key / free-account / account / paid / order / metadata-only / viewer-only / none-open.
- WMS/WMTS/ArcGIS requests in the registries are all in EPSG:3857; where an entry says 'EPSG:3857 accepted' the service reprojects, the native CRS is usually national (see `projection` in the JSON).
- Entries whose endpoint starts with `http://` (Luxembourg WMS, a few Italian/Spanish/Slovenian services) are as seen in the source; try `https://` first.
- Parameters shown under each endpoint are truncated; the JSON `params` / `notes` fields are complete. Layer ids come from fetched files, never guessed; unknown = empty.

## 3. Biggest gaps and caveats

- No byte-level verification outside the reachable AWS S3 hosts (Luxembourg, swisstopo, Copernicus, plus the owner's Scotland bucket): everything marked 'file' or 'search' is a URL/layer id seen in a fetched third-party or official file (or a search snippet), not a tested endpoint. Registry/Freemap/survey claims are dated 2026-09-02 .. 2026-10-05.
- CORS is known (and only as a third-party report) for the terrain-viewer registry services; otherwise unknown. A browser overlay on a non-listed host needs a proxy or a server-side tile cache.
- Historic MAP services are missing or viewer-only for Czechia, Croatia, Portugal, Finland, Lithuania, Slovenia (Franciscan cadastre), Poland (official) and most German Laender (NRW, Hesse, Lower Saxony, Thuringia, Saxony-Anhalt, MV, RLP, Saarland).
- Austria has no national LiDAR WCS and no national historic-map service (only Styria/Vienna cadastre); BEV INSPIRE WMS needs registration; Lower Austria services send no CORS.
- Account/key-gated LiDAR: Denmark (token), Sweden (Geotorget account), Portugal (OAuth), Finland (API key), Lithuania, Spain national >=2 m (session portal); order-only: Italy PCN 1 m; e-mail basket: Wallonia, Slovakia.
- Northern Ireland inland LiDAR, Croatian LiDAR and Lithuanian anonymous LiDAR have no open endpoint; fallback is Copernicus GLO-30 (30 m).
- Ireland: no tile URL for the Tailte Eireann 6-inch series (covered only via the owner's NLS tiles); historic aerial epochs are commercial.
- Books: archive.org / BHL identifiers for Pitt-Rivers, Colt Hoare, Stukeley, RCHME, RCAHMS could not be verified (archive.org is blocked here and GitHub searches for guessed ids returned nothing); only Borlase (two ids) was found earlier. The 17 book entries are mostly 'memory'.
- Phase-3 hosts that ask for credentials were left alone: no tokens, API keys or passwords found in public repos or ELI entries were reused (Swedish shared token, Danish tokens, Hexagon logins).

## 4. Reproducing the byte-level checks (reachable S3 hosts)


```bash
# --- Luxembourg (CC0) ---------------------------------------------------------------
B=https://s3.eu-central-1.amazonaws.com/download.data.public.lu
curl -sI -H 'Origin: https://example.org' \
  "$B/resources/bd-l-lidar2024-releve-3d-du-territoire-luxembourgeois/20241223-093912/MNT_Lidar2024.tif"
#  -> 200, Accept-Ranges: bytes, access-control-allow-origin: *, Content-Length ~40 GB
curl -s "$B/resources-2025-07-09-11-57.csv" | head        # manifest of all 72,868 Luxembourg open-data resources (52.9 MB)

# --- Switzerland (swisstopo OGD) ----------------------------------------------------------
S=https://s3.eu-west-1.amazonaws.com/data.geo.admin.ch
curl -sI "$S/ch.swisstopo.swissaltiregio/swissaltiregio/swissaltiregio_2056_5728.tif"   # 10.1 GB COG, CORS *
curl -sI "$S/ch.swisstopo.swissalti3d/swissalti3d_2019_2600-1200/swissalti3d_2019_2600-1200_0.5_2056_5728.tif"
for y in 2018 2019 2020 2021 2022 2023 2024; do   # which DOP10 vintages exist for a tile (403 = absent)
  curl -s -o /dev/null -w "$y %{http_code}\n" -r 0-0 "$S/ch.swisstopo.swissimage-dop10/swissimage-dop10_${y}_2600-1200/swissimage-dop10_${y}_2600-1200_0.1_2056.tif"
done                                               # observed: 2018/2021/2024 -> 206 ; 2019/2020/2022/2023 -> 403

# --- Copernicus GLO-30 (fallback) ---------------------------------------------------------
curl -sI https://copernicus-dem-30m.s3.eu-central-1.amazonaws.com/Copernicus_DSM_COG_10_N51_00_W002_00_DEM/Copernicus_DSM_COG_10_N51_00_W002_00_DEM.tif
```

## 7. Method and limits

- Discovery: about a dozen WebSearch queries, then (after the search budget was exhausted) GitHub code search for exact layer ids / URLs and `raw.githubusercontent.com` fetches at pinned commit SHAs; no search-engine workaround, no proxy, no attempt to bypass the sandbox allow-list.
- Third-party catalogues relied on (all read as data, never executed): osmlab/editor-layer-index, nico579/lidar2map, mapterhorn/mapterhorn, zymazza/mazzap, osmbe/historical-map, jo-chemla/terrain-viewer, FreemapSlovakia/freemap-v3-react, fabio-rovai/open-ontologies (heritage-aerial), IGNF/cartes-ign-app, geoadmin/doc-tech, compgen-ev/domus, opengeos/*, and several small web-map repos.
- Verified here: Luxembourg and Swiss S3 objects (HEAD, ranged GET, GDAL/rasterio metadata + window reads, CORS header), Copernicus GLO-30, a listing of the owner's Scotland bucket, and the ELI/lidar2map/Mapterhorn files.
- Not done: no bulk downloads (largest fetches: a 53 MB Luxembourg manifest CSV and a 28 MB cadastre index, both deleted afterwards; everything else was headers, ranged reads or small files), no repository modified, no credentials reused. Downloaded files were kept in their own directories and parsed with `python3 -I`.
- Dates in `years` are copied from the source files; where a source gives only a layer name the year is derived from the name and flagged in notes.
- Rebuild: `research/work/build/` holds the build scripts (`python3 -I build.py` writes the JSON and probes host reachability, `python3 -I make_md.py` writes this file); `research/work/gh/` keeps the pinned third-party files that the entries cite (terrain-viewer layer registry, Freemap national sources, heritage-aerial survey JSON, ...), so every `[tv]` / `[fm]` / `[ha]` claim can be re-read offline.
